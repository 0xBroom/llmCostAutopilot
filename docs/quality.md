# Quality contract: methodology

This document explains how a served response is checked for quality (issue
#16): the deterministic-checks-first gate, the blind pairwise judge, why the
judge is cross-family, how position bias is measured rather than assumed
away, and the current, honest state of judge validation. Persistence of the
resulting `Verdict` is issue #17's concern; sampling which requests get
checked at all is issue #18's. This document is scoped to the check itself.

## 1. Deterministic checks come first, and they are free

Every request is run through `domain.quality.run_deterministic_checks`
before any judge is ever invoked: JSON/schema validity, required-field
presence (extraction), label-in-allowed-set (classification),
refusal/empty/truncation detection, and gross length-anomaly detection. Each
check is pure and costs nothing — no network call, no LLM invocation — and a
single failure decides the outcome at confidence 1.0 and short-circuits
before any judge call is even considered.

Two task types (`extraction`, `classification`) stop here entirely:
`mode: deterministic` in `config/quality.yaml` means the deterministic suite
alone decides pass/fail. There is nothing probabilistic about "the JSON does
not parse" or "the label is not in the allowed set", so there is nothing for
a judge to add.

## 2. Blind pairwise comparison for open-ended tasks

`summarization`, `reasoning`, and `default` run `mode: pairwise`: once the
deterministic checks pass and the request was already sampled (an input to
this contract, not a decision it makes), the cheap candidate's answer is
compared against a fresh reference answer generated by re-running the same
prompt on a tier-3 model.

The comparison is **blind**: the judge sees two answers labelled "Answer A"
and "Answer B", never which model produced which. Zheng et al. (NeurIPS
2023, ["Judging LLM-as-a-Judge with MT-Bench and Chatbot
Arena"](https://arxiv.org/abs/2306.05685), S1) report a strong LLM judge
reaching "over 80% agreement, the same level of agreement between humans" on
their benchmark. **That 80% is a *parity* target — as good as a second human
rater — not a precision or ground-truth-accuracy target.** This system does
not claim its judge is more accurate than a human; it claims a
well-constructed LLM judge can be roughly as reliable a second opinion as
another human would be, under comparable conditions.

## 3. Cross-family judge selection

`domain.quality.select_judge` never selects the reference model as judge,
and prefers a judge from a different provider family than either the
reference or the candidate (`provider` is the family: `anthropic` /
`openai` / `ollama`). Zheng et al. also name "self-enhancement bias" as an
open concern (S1), and Panickssery et al. (NeurIPS 2024,
["LLM Evaluators Recognize and Favor Their Own
Generations"](https://arxiv.org/abs/2404.13076), S2) find a linear
correlation between a model's self-recognition ability and how much it
prefers its own outputs.

**Evidence-gap disclosure**: neither source in hand gives an extractable
numeric magnitude for that self-preference effect in a setup like this
one's, and no primary source was found addressing this exact three-family
constraint (OpenAI / Anthropic / a local Ollama deployment). Common practice
in the field suggests using an evaluator model from a different family or
lineage than either candidate reduces this risk, and that is the
justification for the cross-family rule here — but this document does not
cite a specific bias-magnitude number for self-preference, and does not cite
a specific number for how independent cross-family judging actually proves
to be, because neither is backed by a verified primary source yet. Selection
records `JudgeIndependence` (`INDEPENDENT` / `DEGRADED_LOCAL` / `UNAVAILABLE`)
on every `Verdict` specifically so this qualitative rule's effect can be
measured empirically later, once enough verdicts accumulate, instead of
staying an unverified assumption forever.

## 4. Position swap and flip-rate as a measured signal, not an assumption

Every pairwise comparison calls the judge **twice**, with which position
(A/B) holds the candidate's answer swapped between the two calls
(`domain.quality.combine_swapped_judgments`). Disagreement is measured on
the *position-independent* outcome (candidate won / reference won / tie),
never on the raw A/B label, so an ordinary unbiased swap is never mistaken
for a flip — the case this is built to catch is a judge that reports the
*same* raw position twice, meaning its preference tracked the position, not
the content that moved between positions.

Why this matters, evidenced: Wang et al. (ACL 2024, arXiv:2305.17926, S3)
found that response-order swap alone let a weaker model "win" on 66 of 80
(82.5%) queries in an adversarial setup — a demonstrated ceiling, not a
typical rate. Two more recent studies converge on a lower typical range: one
(arXiv:2606.13685, S4) reports pairwise preferences flipping roughly 13.6%
of the time on average, with 28% of questions exceeding a 20% flip rate; a
position-bias study (arXiv:2406.07791, S5) reports position-consistency
scores of 0.62–0.84 across models (0.82–0.83 for GPT-4), i.e. roughly
16–38% flip rates even for frontier judges.

This system sets an **inferred, non-authoritative** flip-rate alarm
threshold at roughly **15–20%**: below that, treat the judge's independence
signal as healthy; at or above it, treat that judge/pair as unreliable for
that comparison rather than trusting its verdict blindly. This threshold is
this project's own inference from the converging studies above (S3–S5), not
a single authoritative cutoff drawn from one paper — S3's 82.5% is an
adversarial extreme cited for context, not the operating assumption.

On disagreement, `combine_swapped_judgments` resolves conservatively:
`winner="tie"`, `margin="negligible"` — which `resolve_verdict_label` always
treats as a PASS. A flip is never resolved in the direction that fails the
cheaper candidate; the conservative default is to let the candidate pass
when the two calls disagree about who actually won, rather than have
position noise decide a real cost-saving decision. (Flagged for `sdd-verify`
per tasks.md 4.2: confirm this remains an acceptable conservative default,
not a masked regression signal, as real verdict volume accumulates.)

## 5. Anchored rubric, not "rate the quality"

RULERS (arXiv:2601.08654, S6) documents that LLM judges show central-tendency
bias on broad, unanchored scales, and that narrow, behaviorally-anchored
scales are the documented fix. The judge prompt built by
`domain.quality.build_judge_prompt` gives concrete 1/3/5 behavioral anchors
for every scored dimension (`correctness`, `completeness`,
`instruction_following`, `format`) rather than an open "rate 1–10" — see
`_DIMENSION_ANCHORS` in `domain/quality.py` for the exact anchor text. The
prompt version is recorded on every judgment and verdict
(`judge_prompt_version`, currently `qj-1.0`), so a future rubric-wording
change is traceable against the scores it produced.

## 6. Ties are a PASS, not an error

"Pairwise or Pointwise? Evaluating Feedback Protocols for Bias in LLM-Based
Evaluation" (arXiv:2504.14716, S7) reports tie rates of roughly 24–45% across
setups, and argues ties more often reflect genuine ambiguity between two
comparably good answers than judge error — and that excluding ties from an
agreement calculation improves measured agreement, because forcing a winner
where none clearly exists is itself a source of noise. Consistent with that,
this contract treats `winner="tie"` as `VerdictLabel.TIE`, and
`Verdict.is_pass` treats `TIE` the same as `PASS`: "no meaningful difference
from the reference" is a legitimate outcome for a cheaper candidate, not a
failure to be forced into a binary.

## 7. Judge validation: current status — PENDING human labelling

**The judge-agreement figure this project would eventually report here is
not yet available, and this document does not fabricate one.**

The plan, once available:

- A committed set of `n=15` human-labelled verdicts,
  `tests/fixtures/quality/validation_set_v1.jsonl`, one JSON object per line.
  Each row's schema: `id`, `task_type`, `judge_winner` (the judge's resolved,
  position-independent outcome — `"candidate"` / `"reference"` / `"tie"`),
  `judge_margin`, `human_label` (the same domain, filled in by a human
  reviewer, or `null` for a row still pending), and — while pending — an
  explicit `"TODO": "awaiting human label"` marker.
- As shipped in this slice, the fixture contains only a **small number of
  placeholder rows demonstrating that exact schema** — every row's
  `human_label` is `null` and every row carries the `TODO` marker. **No row
  in the committed fixture is a real human judgment**, and none of the rows
  below have been reviewed by a person. A human reviewer must independently
  label the full `n=15` set before an agreement figure can be reported here.
- `infrastructure.quality_validation_report.compute_agreement` is the
  harness that will compute the figure once that labelling exists: it counts
  agreement only over rows where `human_label` is set, and returns
  `agreement_rate=None` (never a fabricated `0%` or `100%`) when nothing is
  labelled yet — which is exactly the committed fixture's current state.
  Its correctness is covered by tests against clearly-synthetic in-test rows
  (`tests/unit/test_quality_docs.py`), never against invented "real" human
  judgments.
- **The small-sample caveat, computed by this project (not attributed to any
  cited source)**: at `n=15`, a naive count of, say, 12/15 (80%) agreement
  carries a 95% Wilson confidence interval of roughly **[55%, 93%]** — far
  too wide to certify an 80% parity claim, but wide enough to still catch a
  grossly broken rubric (a true agreement rate around 40–50% would very
  likely produce a confidence interval that does not reach 80%). Sauro &
  Lewis (["Binomial Confidence Intervals for Small-Sample Usability
  Studies"](https://measuringu.com/papers/sauro-lewisHFES.pdf), S8) is cited
  only as the generic statistical grounding for *why* Wilson/Agresti-Coull
  intervals are used instead of a naive Wald interval at this sample size —
  the `[55%, 93%]` figure itself is this project's own arithmetic on its own
  hypothetical 12/15 example, not a number drawn from S8 or any other source.
- Once the full `n=15` human-labelled set is committed, this section will
  report: the observed agreement rate, `n=15`, and the same Wilson-interval
  caveat computed against the actual observed count — not the illustrative
  12/15 above.

Until then: **the agreement figure is PENDING.** Any number appearing above
this paragraph in a future revision must be traceable to a human-reviewed
`validation_set_v1.jsonl` with `human_label` set on all 15 rows and no
remaining `TODO` markers.
